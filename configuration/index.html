    Настройка¶

    Первоначальная настройка подключения¶

    1. Перейдите в Настройки > Устройства и службы > Добавить интеграцию
    2. Найдите "Sber Smart Home MQTT Bridge"
    3. Введите учётные данные MQTT:
    Параметр Обязательный По умолчанию Описание
    MQTT Логин Да -- Логин из проекта Sber Studio
    MQTT Пароль Да -- Пароль из проекта Sber Studio
    MQTT Брокер Нет mqtt-partners.iot.sberdevices.ru Адрес брокера
    MQTT Порт Нет 8883 Порт брокера (TLS)
    Проверять SSL Нет Да Проверка сертификата брокера

    SSL-сертификат

    По умолчанию интеграция проверяет SSL-сертификат MQTT-брокера Sber. Если вы используете нестандартный CA или испытываете проблемы с подключением, можно отключить проверку.

    Параметры интеграции (кнопка «Настроить»)¶

    Основное управление устройствами — в панели Sber Bridge в боковом меню. Окно параметров интеграции — запасной путь без панели: Настройки > Устройства и службы > Sber Smart Home MQTT Bridge > Настроить.

    На первом экране поле «Что вы хотите сделать?»:

    Действие Что происходит
    Entity type preview (N) Список экспортируемых сущностей, сгруппированных по категориям Sber; ✏️ — тип задан вручную. Ничего не меняет
    Open Sber Bridge panel (recommended) Закрывает окно без изменений — дальше работайте в панели
    Advanced entity management (fallback) Открывает меню «Расширенные настройки» из трёх разделов, описанных ниже

    Выбор сущностей¶

    Режим Что делает
    Select entities manually Список с поиском: отмеченные сущности экспортируются, снятые — убираются из Сбера
    Add all entities by domain Добавляет включённые сущности выбранных доменов HA к уже выбранным. От одного устройства HA берётся одна сущность — та, которой Сбер управляет полнее всего (см. «Умная дедупликация»)
    Add entities by label Добавляет к уже выбранным все поддерживаемые сущности, у которых есть хотя бы одна из выбранных меток HA
    Add ALL supported entities Заменяет список всеми поддерживаемыми сущностями (с дедупликацией по устройствам)
    Remove ALL entities Очищает список: мост отправляет в Сбер конфигурацию без устройств, и они пропадают из приложения

    Умная дедупликация (только в режимах «по доменам» и «ВСЕ»): если устройство HA регистрирует несколько сущностей, например light.кухня и switch.кухня, добавляется одна — с наивысшим приоритетом домена: light > cover > climate > water_heater > humidifier > vacuum > media_player > fan > valve > lock > switch > script > button, input_boolean, event > binary_sensor > sensor. Сущности без устройства HA добавляются всегда.

    Переопределение типов устройств¶

    Для каждой экспортируемой сущности — выпадающий список категорий Sber. Auto (по умолчанию) — категория определяется по домену и device_class. Меняйте, если автоматика ошиблась: например, switch с лампой → light, или реле → socket, чтобы в приложении была иконка розетки. Если ни одна сущность ещё не выбрана, раздел сообщает об этом и закрывается.

    Категории, которые предлагает список (идентификатор — название в интерфейсе): curtain — Curtain, gate — Gate / Garage, hvac_ac — Air conditioner, hvac_air_purifier — Air purifier, hvac_boiler — Boiler, hvac_fan — Fan, hvac_heater — Heater, hvac_humidifier — Humidifier, hvac_radiator — Radiator, hvac_underfloor_heating — Underfloor heating, intercom — Intercom, kettle — Kettle, led_strip — LED strip, light — Light, relay — Relay, scenario_button — Scenario button, sensor_air — Air quality, sensor_door — Door / Window, sensor_gas — Gas, sensor_pir — Motion, sensor_smoke — Smoke, sensor_temp — Temperature, sensor_water_leak — Water leak, socket — Socket, tv — TV / Media player, vacuum_cleaner — Vacuum, valve — Valve, window_blind — Window blind.

    Тайминги синхронизации устройств¶

    Сбер считает каждую публикацию конфигурации полным списком устройств: устройство, которого в ней нет, облако удаляет, а когда оно появляется снова — заводит заново в комнате хаба. Поэтому при запуске и после изменений мост ждёт, пока устройства получат состояние.

    Параметр По умолчанию Диапазон Назначение
    Окно затишья, с (config_settle_delay) 5 0–300 Пока устройства ещё загружаются, список публикуется, когда столько секунд подряд не появилось ни одного нового. Если все устройства уже загружены, список уходит сразу. Увеличьте, если после перезапуска HA устройства переезжают в комнату хаба — например, батарейные Zigbee-датчики просыпаются медленно
    Максимальное ожидание устройств, с (config_max_wait) 120 1–900 Верхняя граница ожидания: по её истечении список публикуется без не загрузившихся устройств, а в журнал пишется предупреждение с их именами. Увеличьте для большой Zigbee/Z-Wave-сети, уменьшите, если сущность, которая никогда не загрузится, задерживает публикацию остальных

    Ожидание держат только устройства, которые Сбер уже знает: новое устройство, ещё не загрузившееся, просто появится в одной из следующих публикаций. Оба параметра дублируются на вкладке Настройки панели и применяются без перезапуска интеграции.

    Параметры моста (вкладка «Настройки» панели)¶

    Панель Sber Bridge > вкладка Настройки. Значения сохраняются кнопкой Сохранить и применяются к работающему мосту без перезапуска интеграции; Reset to Defaults подставляет значения по умолчанию (их тоже нужно сохранить). Значение вне диапазона отклоняется целиком — ни один параметр из запроса не сохраняется.

    Параметр По умолчанию Диапазон Назначение и когда менять
    Мин. интервал переподключения, с (reconnect_interval_min) 5 1–3600 Пауза перед первой повторной попыткой после обрыва связи; каждая неудачная попытка удваивает паузу. К этому значению пауза возвращается после сессии, продержавшейся 60 секунд. Увеличьте, если брокер отвергает слишком частые подключения
    Макс. интервал переподключения, с (reconnect_interval_max) 300 1–86400 Потолок, до которого растёт пауза между попытками. Уменьшите, чтобы после долгого отсутствия интернета мост возвращался быстрее. Задавайте не меньше минимального интервала
    Проверять SSL-сертификат (sber_verify_ssl) включено вкл/выкл Проверка TLS-сертификата брокера. Выключайте только если брокер использует собственный или самоподписанный сертификат. Применяется при следующем подключении
    Задержка перед отправкой состояния, с (debounce_delay) 0.1 0–60 Изменения состояний, пришедшие в пределах этого окна, отправляются в Сбер одним сообщением; при непрерывном потоке изменений отправка всё равно происходит не реже, чем раз в пять таких окон. 0 — отправлять сразу. Увеличьте, если устройства шлют много мелких обновлений подряд
    Макс. размер пакета MQTT, байт (max_mqtt_payload_size) 1000000 1024–10000000 Входящие сообщения от Сбера крупнее этого размера отбрасываются с предупреждением в журнале — защита от переполнения памяти. Менять обычно не нужно
    Пауза перед отправкой конфигурации, с (config_settle_delay) 5 0–300 То же, что «Окно затишья» в параметрах интеграции (см. выше)
    Макс. ожидание загрузки устройств, с (config_max_wait) 120 1–900 То же, что «Максимальное ожидание устройств» (см. выше)
    Отложенное подтверждение состояния, с (confirm_delay) 1.5 0–60 Через столько секунд после команды из Сбера мост ещё раз отправляет состояние устройства — чтобы в приложении оказались атрибуты, которые HA обновляет с задержкой. Увеличьте для медленных устройств, у которых после команды в приложении остаётся старое значение
    Задержка проверки на молчаливое отклонение, с (ack_audit_delay) 60 1–3600 Через столько секунд после публикации конфигурации мост проверяет, какие устройства Сбер так и не подтвердил, и пишет предупреждение в журнал. Новое значение действует для проверок, запланированных после сохранения
    Размер журнала сообщений MQTT (message_log_size) 50 1–10000 Сколько последних записей хранят журналы вкладки «Инструменты» (сообщения MQTT, трассировки, изменения состояний, ошибки проверки, подтверждения команд). Увеличьте на время отладки: записи хранятся в памяти
    Назначать parent_id автоматически (hub_auto_parent_id, карточка «Устройство-хаб») выключено вкл/выкл Всем устройствам без явного parent_id проставляется parent_id: root — они становятся дочерними устройствами хаба моста. Применяется при следующей публикации конфигурации
    Добавлять метку ha_serial_number (ha_serial_number_enabled) выключено вкл/выкл Добавляет в partner_meta.ha_serial_number каждого устройства серийный номер или MAC из реестра устройств HA, а без них — метку этого экземпляра HA (ha-<8 символов>). Включайте, если пользуетесь интеграцией, которая импортирует устройства Сбера обратно в HA: по метке она распознаёт петлю. Применяется при следующей публикации конфигурации
    Показывать уведомление о молчаливом отклонении (silent_rejection_alerts) выключено вкл/выкл Устройства, которые Сбер ни разу не подтвердил, показываются уведомлением в Настройки > Ремонт. По умолчанию выключено: Сбер может часами не запрашивать состояние принятого устройства, и уведомление было бы ложным. Данные проверки в любом случае видны в панели и в журнале

    Настройки отдельных устройств¶

    Открываются кликом по устройству в таблице панели. Сохраняются для конкретной сущности и применяются без перезапуска интеграции.

    Импульсные ворота (категория gate, реле switch / button / script со связанным датчиком положения):

    Параметр По умолчанию Диапазон Назначение
    Инвертировать геркон (invert_contact) выключено вкл/выкл Включите, если связанный датчик показывает on при закрытых воротах
    Сервис импульса (impulse_service) auto auto, toggle, turn_on Только для реле switch: auto и toggle вызывают switch.toggle, turn_on — switch.turn_on. Для button всегда вызывается press, для script — turn_on
    Время хода створки, с (travel_time) 0 0–600 0 — выключено: положение меняется только по датчику. Со значением ворота сразу после импульса сообщают «открываются» / «закрываются»; всё это время приложение Сбера блокирует кнопку управления
    Автозакрытие через, с (auto_close_time) 0 0–3600 Укажите ту же задержку, через которую плата ворот сама закрывает створку. 0 — выключено. По истечении ворота сообщают «закрываются», пока датчик не скажет иное. Задайте заодно время хода: без него «закрываются» держится 30 секунд

    Чайник (категория kettle, water_heater с режимами работы):

    Параметр По умолчанию Допустимые значения Назначение
    Режим «выключено» (off_mode) автоопределение (off) режим из operation_list сущности Режим HA, которым мост выключает чайник
    Режим «кипячение» (boil_mode) автоопределение (boil) режим из operation_list Режим HA для кипячения
    Режим «нагрев до температуры» (heat_mode) автоопределение (heat, electric, eco, gas, heat_pump, high_demand, performance — первый найденный) режим из operation_list Режим HA для нагрева до заданной температуры

    Меняйте режимы, если автоопределение не нашло нужный (панель показывает, какой режим сейчас используется). Если режим не найден или чайник не сообщает режимов, мост просто включает и выключает его.

    Датчик температуры (категория sensor_temp): параметр temp_unit_view (по умолчанию true) решает, публиковать ли функцию temp_unit_view — шкалу отображения температуры. Отдельного поля в панели нет: нажмите Экспорт на панели инструментов, в файле задайте "gate_options": {"sensor.<имя>": {"temp_unit_view": false}} (блок gate_options хранит настройки всех устройств, не только ворот) и загрузите файл через Импорт. Выключайте, только если нужен минимальный набор функций: изменение набора функций заставляет Сбер зарегистрировать устройство заново, и оно теряет комнату.

    Предварительный просмотр типа устройства (Entity Preview)¶

    При выборе или переопределении типа устройства интеграция показывает Entity Preview — список features Sber, которые будут опубликованы для выбранного типа. Это позволяет до сохранения убедиться, что выбранная категория соответствует реальным возможностям устройства.

    Entity Preview доступен: - В мастере добавления (Sidebar Panel > Add Device Wizard, шаг 1) - В параметрах интеграции: действие Entity type preview показывает итоговую категорию Sber каждой экспортируемой сущности

    Кастомизация через YAML (configuration.yaml)¶

    Помимо UI-настроек, вы можете настроить entity через configuration.yaml. Это удобно для автоматизации и хранения конфигурации в Git.

    Базовый синтаксис¶

    sber_mqtt_bridge:
  entity_config:
    <entity_id>:
      sber_type: <категория>    # необязательно
      sber_name: "<имя>"        # необязательно
      sber_room: "<комната>"    # необязательно

    Параметры¶

    Параметр Тип Описание
    sber_type string Переопределить категорию устройства в Sber. Доступные значения: light, relay, socket, curtain, window_blind, gate, hvac_ac, hvac_radiator, valve, hvac_humidifier, scenario_button
    sber_name string Имя устройства, которое будет отображаться в приложении Сбер и при голосовом управлении через Салют
    sber_room string Комната, к которой будет привязано устройство в Сбер. Название должно совпадать с названием комнаты в приложении Сбер

    Приоритет настроек¶

    Настройки применяются с учётом приоритетов (от высшего к низшему):

    1. Переопределение в приложении Сбер (rename/change_group) — имеет наивысший приоритет для имени и комнаты
    2. Переопределение в UI (Options Flow → Переопределение типов) — для типа устройства
    3. YAML конфигурация (configuration.yaml) — используется если нет UI-переопределения
    4. Автоматическое определение — по домену и device_class HA entity

    Примеры¶

    Пример 1: Переключатель как свет¶

    Zigbee-реле управляет светильником, но HA видит его как switch. Чтобы в Сбер он отображался как лампочка:

    sber_mqtt_bridge:
  entity_config:
    switch.kitchen_light:
      sber_type: light
      sber_name: "Свет кухня"
      sber_room: "Кухня"

    Результат: в приложении Сбер появится устройство "Свет кухня" с иконкой лампочки в комнате "Кухня". Команда "Салют, включи свет на кухне" будет работать.

    Пример 2: Несколько устройств с именами и комнатами¶

    sber_mqtt_bridge:
  entity_config:
    # Свет
    light.living_room:
      sber_name: "Люстра"
      sber_room: "Гостиная"

    light.bedroom_lamp:
      sber_name: "Ночник"
      sber_room: "Спальня"

    # Реле → свет
    switch.hallway_relay:
      sber_type: light
      sber_name: "Свет коридор"
      sber_room: "Коридор"

    # Датчики
    sensor.outdoor_temperature:
      sber_name: "Температура на улице"
      sber_room: "Двор"

    # Шторы
    cover.bedroom_curtain:
      sber_name: "Шторы спальня"
      sber_room: "Спальня"

    Пример 3: Только имена (без изменения типа)¶

    Если тип определяется корректно, но нужны русские имена:

    sber_mqtt_bridge:
  entity_config:
    light.0xa4c138827efe2255_l1:
      sber_name: "Кухня основной"
    light.0xa4c138827efe2255_l2:
      sber_name: "Кухня второй свет"
    sensor.temperature_living_room:
      sber_name: "Температура гостиная"

    Пример 4: Переопределение комнат для организации в Сбер¶

    sber_mqtt_bridge:
  entity_config:
    # Все датчики — в одну "комнату" для удобства
    sensor.temp_bathroom:
      sber_room: "Ванная"
    sensor.humidity_bathroom:
      sber_room: "Ванная"
    binary_sensor.motion_hallway:
      sber_room: "Прихожая"
    binary_sensor.door_front:
      sber_room: "Прихожая"

    Перезагрузка

    После изменения configuration.yaml необходимо перезагрузить Home Assistant (или перезагрузить интеграцию через UI) для применения изменений.

    Совмещение UI и YAML

    YAML-конфигурация и UI-настройки работают вместе:

    • Выбор entity (какие устройства экспортировать) — только через UI (Options Flow)
    • Тип устройства — можно через UI или YAML (UI приоритетнее)
    • Имя и комната — можно через YAML или приложение Сбер (Сбер приоритетнее)

    Управление устройствами в приложении Сбер¶

    После добавления устройств:

    1. Откройте приложение Сбер Умный дом
    2. Устройства появятся автоматически (может занять 10-30 секунд)
    3. Переименовать устройство: нажмите на устройство > иконка настроек > измените имя
    4. Назначить комнату: нажмите на устройство > иконка настроек > выберите комнату
    5. Голосовое управление: скажите, например, "Салют, включи свет на кухне"

    Примеры голосовых команд:

    Команда Что делает
    "Салют, включи свет на кухне" Включает light.kitchen
    "Салют, выключи всё" Выключает все устройства
    "Салют, какая температура в спальне?" Читает sensor.temp_bedroom
    "Салют, закрой шторы" Закрывает cover.curtain
    "Салют, установи температуру 23 градуса" Устанавливает climate.hvac на 23°C
    "Салют, включи увлажнитель" Включает humidifier.*

    Переименования и комнаты из Сбер

    Переименования и назначения комнат, сделанные в приложении Сбер, сохраняются локально в интеграции и будут включены в будущие публикации конфигурации. Они имеют приоритет над YAML-настройками sber_name и sber_room.

    Add Device Wizard (Мастер добавления) — v1.26.0 type-first¶

    Пошаговый мастер для добавления нового устройства в device-centric режиме: сначала тип Sber, потом HA-устройство целиком вместе с его датчиками.

    1. Шаг 1 — Тип устройства: сетка категорий Sber, сгруппированных по разделам Control / Sensors / Automations. Каждая карточка — иконка и название категории.
    2. Шаг 2 — HA device: список всех HA-устройств, чья primary entity промотируется в выбранную категорию (на базе CATEGORY_DOMAIN_MAP). Карточка устройства раскрывается и показывает:
      • Primary entity (с radio-переключателем при нескольких кандидатах)
      • Linked native: родные датчики того же устройства (батарея, сигнал, температура, влажность и т.п.) — предвыбранны
      • Linked compatible: совместимые датчики с других устройств (помечены чипом from: {origin}) — opt-in
      • Unsupported: прочие entity для контекста (greyed out) Guard ролей: если вы отмечаете датчик с той же ролью, что и уже выбранный, предыдущий автоматически снимается.
    3. Шаг 3 — Имя, комната, подтверждение: задать отображаемое имя и комнату для Sber, затем одним кликом выполнить атомарное добавление (экспорт primary + запись type override + entity_links + redefinitions в config entry, один reload).

    Связывание entity через Sidebar Panel¶

    В v1.26.0 Entity Linking встроен прямо в новый type-first Add Device Wizard — отдельный отдельный шаг больше не нужен. Linked-native датчики предвыбраны автоматически при показе карточки устройства, cross-device совместимые — доступны в том же окне как opt-in.

    Для пост-редактирования связей (после добавления устройства) используйте sber-link-dialog в таблице устройств: нажмите на primary entity, откроется диалог с candidate-датчиками (backend команда sber_mqtt_bridge/suggest_links, тонкая обёртка над HaDeviceGrouper.preview_for_category).

    Связи хранятся в config_entry.options.entity_links и переживают перезапуск HA.

    Сущности интеграции¶

    Интеграция создаёт служебное устройство Sber MQTT Bridge с диагностическими сущностями — по ним удобно строить автоматизации на потерю связи. Пока мост остановлен, сущности недоступны.

    Сущность Тип Значение
    Подключение к Сберу binary_sensor (connectivity) Включён, пока мост держит соединение с брокером Сбера
    Фаза подключения sensor (enum) «Запуск», «Подключение», «Ожидание Сбера», «Готов», «Логин или пароль отклонён», «Отключён»
    Устройств известно Сберу sensor Сколько экспортируемых устройств, по данным моста, есть в облаке Сбера
    Устройств не подтверждено Сбером sensor Сколько экспортируемых устройств облако ни разу не подтвердило
    Ошибок от Сбера sensor (total increasing) Счётчик сообщений об ошибках, присланных облаком
    Код последней ошибки Сбера sensor Код последней ошибки, присланной облаком

    Реаутентификация¶

    Если учётные данные MQTT стали недействительны (например, вы сменили пароль в Sber Studio), Home Assistant предложит пройти реаутентификацию. Перейдите в настройки интеграции и обновите пароль.

    Как удалить интеграцию и убрать устройства из Сбера — см. Удаление интеграции.
