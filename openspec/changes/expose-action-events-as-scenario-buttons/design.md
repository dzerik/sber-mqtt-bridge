# Design

## Context

Существующий `ScenarioButtonEntity` уже отслеживает новые значения состояния,
держит исходное значение и исключает опубликованное нажатие из последующих
снимков. Точка расширения — распознавание timestamp-доменов и значения клика.
См. proposal.md для мотивации и источников протокола.

## Goals / Non-Goals

**Goals:** одинаковый экспорт событий `input_button` и `scene`, проверка через
настоящие HA services и MQTT publisher, понятное направление в мастере.

**Non-Goals:** импульсный relay, изменение существующего debounce, гарантированная
доставка каждого события при обрыве сети, перенос содержимого HA-сцены в Sber.

## Decisions

- Дополнить единую карту доменов категории `scenario_button`; не вводить новый тип Sber.
- Для новых доменов `unknown` означает отсутствие предыдущей активации, а не offline.
- Каждое новое время активации преобразовывать в `click`; доступные значения ограничить `click`.
- Сохранить существующий механизм исходного состояния, diff и потребления события после публикации.
- Отдельный класс отклонён: он дублирует существующий протокол разовых событий.
- `relay` отклонён для этого change: добавляет искусственное состояние и противоположное направление.
- Для живой проверки использовать отдельные тестовые сущности, без запуска пользовательских сцен.

## Risks / Trade-offs

- Быстрые изменения внутри одного debounce могут объединиться, как у существующих кнопок → явно сохранить это ограничение; последовательные активации после отправки проверять отдельно.
- Наличие устройства в MQTT config не доказывает срабатывание пользовательского сценария в облаке → различать отправку, принятие устройства и фактическое исполнение сценария.
- Документация `button_event` неоднозначна относительно обратного управления → не считать исходящую отправку доказательством обратного запуска HA.
- Старая версия мастера кешируется → поднять beta штатным скриптом перед деплоем.

## Migration Plan

Новые домены становятся доступны для явного добавления, существующий список
экспорта сохраняется. Деплой с копией предыдущей директории; откат файловый,
тестовые экспорты убрать через API после проверки.
